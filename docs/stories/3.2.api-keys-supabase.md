# Story 3.2: Migrar API keys para Supabase

## Status

## Story
**As a** usuario do teamAI,
**I want** que minhas API keys sejam armazenadas no Supabase encriptadas,
**so that** minhas keys estejam seguras no servidor e acessiveis em qualquer dispositivo.

## Acceptance Criteria
1. Settings UI ainda funciona (UX identica ao usuario)
2. Keys salvas na tabela Supabase `user_api_keys` (user_id, provider, encrypted_key)
3. Keys nunca em localStorage apos migracao
4. Migracao automatica de keys existentes no localStorage para Supabase no primeiro login
5. Encriptacao verificada (keys nao legiveis em texto plano no Supabase)

## Dev Notes

### Arquivos relacionados no big-AGI
- `src/modules/llms/vendors/` — cada vendor (anthropic, openai, gemini, etc.) tem setup com API key
- `src/modules/llms/vendors/useServiceSetup.ts` — hook compartilhado para setup de vendors
- `src/common/stores/llms/store-llms.ts` — Zustand store principal dos LLMs (persiste em localStorage)
- `src/modules/aix/server/` — server-side que recebe API keys para chamadas LLM
- `src/server/env.server.ts` — env vars do servidor (keys server-side como `OPENAI_API_KEY`)

### Padroes existentes a seguir
- Zustand stores: usar `persist` middleware com `localStorage` (atual), migrar para tRPC calls
- tRPC: routers em `src/server/trpc/`, schema validation com Zod
- Vendors: cada vendor implementa `IModelVendor` interface em `src/modules/llms/vendors/IModelVendor.ts`
- Encriptacao: usar `pgcrypto` extension do PostgreSQL ou encriptacao application-level

### APIs e tipos relevantes
- `IModelVendor` em `src/modules/llms/vendors/IModelVendor.ts`
- `store-llms.ts` tipos: onde API keys ficam atualmente no state
- Supabase tabela: `user_api_keys (id, user_id, provider, encrypted_key, created_at, updated_at)`

### Estrategia de encriptacao
- Opcao 1: `pgcrypto` no PostgreSQL — `pgp_sym_encrypt(key, secret)` / `pgp_sym_decrypt()`
- Opcao 2: Encriptacao application-level no Edge Function com `ENCRYPTION_SECRET` env var
- Recomendacao: pgcrypto para simplicidade, secret armazenado como env var do Supabase

### Testing
- Framework: vitest
- Localizacao dos testes: colocados ao lado do arquivo
- O que testar: upsert/get/delete de keys, migracao de localStorage, encriptacao roundtrip
- Testar que key encriptada != key original no banco
- Testar que usuario A nao acessa keys do usuario B (RLS)
