## Story
**As a** administrador do teamAI,
**I want** fazer deploy do big-AGI fork via Docker Compose com todas as configuracoes,
**so that** o sistema rode self-hosted com dominio proprio e configuracao simples.

## Acceptance Criteria
1. Dockerfile multi-stage atualizado para teamAI (base existente em `/Dockerfile`)
2. `docker-compose.yml` com servicos (big-agi, variaveis de ambiente Supabase)
3. `.env.example` documentado com todas as variaveis necessarias
4. Symlinks preservados no container (Linux nativo)
5. Dominio proprio configuravel via variavel de ambiente
6. Health check funcional (`/api/health` ou similar)

## Dev Notes

### Arquivos relacionados no big-AGI
- `Dockerfile` — multi-stage existente (base `node:24-alpine`, 3 stages: deps, builder, runner)
- `docker-compose.yaml` — compose simples existente (servico `big-agi`, porta 3000, `env_file: .env`)
- `docs/deploy-docker.md` — documentacao de deploy Docker existente
- `docs/deploy-reverse-proxy.md` — documentacao de reverse proxy existente
- `src/server/env.server.ts` — todas as env vars do servidor

### Padroes existentes a seguir
- Dockerfile usa `NODE_ENV=development` para deps (npm ci com devDeps) e `NODE_ENV=production` para build/run
- Runner stage copia seletivamente de builder (nao copia `.next/cache`)
- User non-root: `nextjs:nodejs` (uid/gid 1001)
- Compose usa `env_file: .env` para carregar variaveis

### Estrutura do Dockerfile existente
```
FROM node:24-alpine AS base       # ENV NEXT_TELEMETRY_DISABLED=1
FROM base AS deps                 # COPY package*.json, npm ci
FROM base AS builder              # COPY --from=deps, npm run build, npm prune --omit=dev
FROM base AS runner               # COPY --from=builder, USER nextjs, EXPOSE 3000, CMD next start
```

### Volumes necessarios
- Repo teamai: `${TEAMAI_REPO_PATH}:/app/teamai-repo:ro` — somente leitura, para minds/metadata
- Nao precisa volume para dados persistentes (Supabase e externo)

### Testing
- Framework: docker compose
- O que testar: build completa, startup sem erros, health check responde, login funciona, minds carregam
- Testar em Linux (ambiente alvo)
- Testar com `.env.example` preenchido com valores reais
